## Threat Model

Targeted phase 2 model for AVANA's Next.js commerce application: administrators authenticate with password and production TOTP, receive a signed two-hour cookie, and require a matching active Supabase session record before protected page reads or API operations. Commerce uses service-role SQL transactions for reservations, payment completion and refunds, with Stripe-confirmed payment data. Development permits an unauthenticated page demo only when neither admin authentication nor privileged Supabase access is configured. CI includes real PostgreSQL concurrency validation and an aggregate Security gate. Evidence: lib/admin-auth.ts:47, lib/admin-auth.ts:61, lib/server/admin-session.ts:12, lib/server/admin-page.ts:8, lib/server/orders.ts:188, lib/server/stripe-checkout.ts:22, .github/workflows/ci.yml:12. This independent review inspected source offline; it did not execute tests or establish remote deployment state. Parent validation subsequently passed 158 Vitest tests, four native PostgreSQL 17.11 concurrency tests and 18 production-browser tests; cloud state remains unverified.

### Attacker Capabilities

- An unauthenticated visitor can submit login attempts, arbitrary cookies and guest checkout requests, including concurrent/repeated requests; this does not grant database service-role, signing-secret or Stripe authority. Existing login, session-registry and checkout controls constrain these inputs. Evidence: app/api/admin/login/route.ts:37, lib/server/admin-session.ts:12, app/api/checkout/session/route.ts:23.
- A holder of a previously copied valid admin token can replay it until expiry or revocation; successful reuse after committed logout would restore terminated administrator authority. The current guard requires an active database record, and revocation affects that record. Evidence: lib/server/admin-session.ts:12, supabase/migrations/20260914010000_admin_sessions.sql:32, supabase/migrations/20260914010000_admin_sessions.sql:40.
- An attacker can send forged webhook requests or cause legitimate retries, but cannot synthesize accepted provider events without the webhook secret. Duplicate legitimate deliveries can contend on SQL state; the reviewed functions lock the order and suppress repeated inventory effects. Evidence: app/api/webhooks/stripe/route.ts:112, supabase/commerce.sql:760, supabase/commerce.sql:1024.
- A contributor can propose code/workflow changes that execute in CI. Repository modification alone does not establish permission to bypass protected-branch checks or access deployment secrets. CI declares contents:read and disables persisted checkout credentials. Evidence: .github/workflows/ci.yml:3, .github/workflows/ci.yml:8, .github/workflows/ci.yml:29.
